# 基金申请书写作参考

配合 `templates/grant-plan.json`、`templates/grant-brief.md`、
`scripts/check_grant_proposal.py` 使用。**task.md 与 organizer-workorder.json 优先**；
材料没有的申请人资历、前期成果、单位信息、预算依据一律写
`not_provided_in_materials`，不要编造。

## 1. 七要素与工作单对齐

| 要素 | 必须回答 | 常见失分 |
|---|---|---|
| E1 背景与科学问题 | 领域现状 → 具体空白 → 可检验问题 | 背景太长、问题不具体 |
| E2 研究目标 | 1 总目标 + 2–4 可考核分目标 | 目标与内容混写 |
| E3 研究内容 | 分任务、逻辑递进 | 内容与目标不对应 |
| E4 方法与技术路线 | 每任务的方法/数据/判据 | 只写方法名 |
| E5 创新点 | 相对已有工作的具体差异 | “首次/国际领先”无对照 |
| E6 可行性 | 理论/方法/数据/团队/条件 | 空喊“实力强” |
| E7 成果与进度 | 产出形式、指标、时间节点 | 指标不可量化 |

一致性：E2 每个分目标都要在 E3 有任务、E4 有方法、E7 有产出；
断链写 `consistency.breaks[]`。

## 2. 要求登记册与资格筛查

从 workorder 拆 `requirements[]`：

```json
{"id":"R1","type":"Section|Limit|Attachment|Evaluation|Eligibility",
 "text":"…","source_location":"workorder#E2","status":"covered|partial|missing"}
```

资格项不满足/未核实标 `eligibility_risk` 并上浮；不要申请不符合资格的项目。

## 3. 事实与缺失

`applicant_evidence`：

```json
{"provided":["materials/prior_work.pdf"],
 "missing":["申请人简历","依托单位信息","经费预算依据"]}
```

`gaps[]` 每条写“缺什么、为什么需要、谁补”。缺失不等于失败，编造才是。

## 4. 预算与周期

- 预算科目必须对应研究内容；无依据的金额写 `to_be_confirmed` 与计算口径。
- 总额必须等于确认的申请金额（若有）；不出现无内容支撑的科目。
- 进度用“阶段—时间—里程碑—交付物”，粒度到季度。

## 5. 评审视角

按四项自检：

1. 重要性：问题是否真重要？
2. 创新性：相对谁、差异是什么？
3. 可行性：方法/数据/团队/条件是否支撑？
4. 产出明确性：指标是否可考核？

红队六问：为什么重要、新在哪、是否可做、有无基础、失败怎么办、是否符合指南。

## 6. 常见失败模式

| 信号 | 问题 | 修复 |
|---|---|---|
| 背景写成综述 | 无具体缺口 | 收敛到一个问题 |
| 目标空泛 | “提高性能/深入研究” | 可检验动词+指标 |
| 三张皮 | 目标/内容/方法各说各话 | 建一致性矩阵 |
| 虚构前期成果 | 材料没有的论文/专利 | 删除或 not_provided |
| 创新喊口号 | “国际领先”无对照 | 具体差异+证据 |
| 预算无支撑 | 科目与内容无关 | 按内容重编 |
| 编造政策 | 虚构指南条款 | 只引材料/公开原文 |

## 7. 交付前检查

- [ ] 七要素齐全或标 `missing`。
- [ ] 每个目标四链齐全（内容/方法/产出/指标）。
- [ ] `applicant_evidence.missing` 与 `gaps` 覆盖缺失项。
- [ ] 预算/周期与内容一致；无虚构金额。
- [ ] 创新点有对照对象。
- [ ] `check_grant_proposal.py` 返回 `ok: true`。
