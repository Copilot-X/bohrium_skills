# 学术汇报叙事与时间预算 Playbook

适用：组会、答辩、会议报告、快报（lightning talk）、跨学科讲座。
目标不是"把论文压成幻灯片"，而是把**已有材料**组织成一条可讲、可核、
按时结束的论证路径：每一页只回答一个问题，每一个论断都能回到源材料。

配套资产：

- `templates/talk-plan.json`：从 section 到 slide 的计划骨架；
- `scripts/check_talk_plan.py`：对计划和 `result.json` 做机器校验。

---

## 1. 先定位，再动笔

动笔前用四句话锁定汇报：

1. **场合**：组会 / 答辩 / 会议 / 快报 / 跨学科讲座。场合决定证据深度与答辩压力。
2. **听众结果**：讲完后希望听众产生什么变化——听懂、相信、做决定、记住。
   不要写"讲完这些内容"；要写"听众能复述哪一句话、同意哪一个判断"。
3. **听众问题**：听众坐下时最想问的一句话。答辩常是"凭什么可信"，
   组会常是"卡在哪里、下一步做什么"，跨学科听众常是"这和我有什么关系"。
4. **唯一 takeaway**：全篇只允许一个。把它写成一句有主语的判断句，
   而不是主题词（"催化剂研究"不是 takeaway，"氧空位是高温选择性的来源"才是）。

`throughline` 必须是听众结果句，且全篇每一页都能回答"你为这句话贡献了什么"。
如果某页删掉后 takeaway 完全不受影响，这页就该进 backup 或删掉。

### 听众适配矩阵

| 维度 | 领域专家 | 相邻领域 | 跨学科/大众 |
|---|---|---|---|
| 背景铺垫 | 1 页以内，直接给 gap | 2–3 页，补关键概念 | 3–4 页，先讲清"为什么难" |
| 方法深度 | 设计选择、对照、统计 | 一张示意图 + 关键决策 | 一句话 + 类比，细节进 backup |
| 结果呈现 | 原图 + 误差/显著性 | 原图 + 一句解读 | 重画的简化图或关键数字 |
| 术语 | 可直接使用 | 首次出现给一句解释 | 每个术语配一句白话 |
| 证据偏好 | 原始数据、消融、复现 | 对照 + 机制解释 | 可感知的案例/数量级 |
| Q&A 压力 | 方法细节与替代解释 | 适用边界 | 意义与应用 |

同一份材料给不同听众时，**保留因果链，改变证据颗粒度**；不要为了"简单"
删掉 tension 和 decision，否则只剩一份没有观点的摘要。

## 2. 故事线：因果弧，不是论文目录

推荐骨架（3–5 幕）：

```
context（世界/问题现状）
  → tension（哪里不行、代价是什么）
  → question（本次要回答的唯一问题）
  → approach / method（为什么这样答）
  → result×N（证据逐层加码）
  → limitation（边界与替代解释）
  → conclusion + action（听众带走什么）
```

规则：

- 相邻两幕必须能用一个"因为/所以/但是"连接。连不上就补桥或删幕。
- 幕的时间占比：开场与问题 ≤ 25%，方法与结果 ≈ 50–60%，局限与结论 ≈ 15–25%。
- 不按论文章节顺序搬运；论文的 Related Work 通常不是汇报的第二页。
- 证据放在怀疑最高点：重大主张之前、大胆承诺之后、转折处。
- 标题连读测试：把每页结论式标题按顺序读一遍，应能复述完整论证；
  如果读起来像目录，说明标题还停留在章节名。

### 常见主线句式

- 组会：`X 在本周数据中成立，但 Y 条件下失效；下一步先排除 Z。`
- 答辩：`现有方法在 A 条件下失效，我们通过 B 机制解决，边界是 C。`
- 会议：`大家以为 A 是瓶颈，我们的对照实验表明真正的瓶颈是 B。`
- 快报：`一个反直觉结果 + 一个可信证据 + 一个明确含义。`
- 跨学科：`一个所有人都见过的现象，背后是一个没被解释的机制。`

## 3. 时间预算：先减后加

### 基本公式

```
可用讲述时间 = 总时长 − Q&A − 缓冲
逐页秒数之和 ≈ 可用讲述时间 × 60
```

- Q&A 建议占总时长 15–25%；答辩可到 30%。
- 留 0.5–1 分钟缓冲给开场、翻页、被打断。
- 单页 45–75 秒；方法细节页可 90 秒，过渡/金句页 15–30 秒。
- 结果部分不少于讲述时间的 30%；方法不超过 30%；开场不超过 15%。

### 时长 → 页数 / 结构

| 总时长 | 建议讲述页数 | 结构骨架 |
|---|---|---|
| 5 min 快报 | 5–7 | 问题 1 页 → 方法 1 页 → 主结果 1–2 页 → 含义 1 页 → 联系页 |
| 10 min | 8–12 | 问题 2 → 方法 2 → 结果 3–4 → 局限/结论 1–2 |
| 15 min 组会/会议 | 10–14 | 问题 2–3 → 方法 2–3 → 结果 4–5 → 局限 1 → 结论 1 |
| 20 min 答辩节选 | 14–18 | 问题 3 → 方法 3–4 → 结果 6–8 → 局限 1–2 → 结论 1 |
| 45 min 答辩 | 30–40 | 按研究目标分 2–3 组，每组 method→result→小结，最后统一讨论 |

页数服从题面；题面给了 `slide_budget` 就必须等量交付。
超时优先删：背景复述 → 方法实现细节 → 次要结果 → 文献对比；
**永远不删**：研究问题、主结果、局限、结论。可删页标 `optional` 并进 backup。

### 超时恢复顺序

1. 跳过 backup 与 optional；
2. 方法压缩成"设计 + 一个关键决策"；
3. 次要结果只留一句"另有两项一致性结果在 backup"；
4. 讨论压缩成两句；
5. 结论与 takeaway 绝不能省。

## 4. 逐页设计：结论式标题 + 证据

每页字段：

| 字段 | 要求 |
|---|---|
| `role` | title / motivation / question / approach / method / result / discussion / limitation / conclusion / summary / transition / acknowledgment |
| `title` | 一句结论，能独立读懂；禁止"结果""方法""背景"等标签 |
| `claim` | 该页唯一主张；与标题同义但更完整，可含条件与数值 |
| `covers` | 对应 `must_cover` 的条目，保证必讲点不丢 |
| `evidence` | 至少一条 `{source, locator, strength}`；locator 精确到 Fig./Table/§/页码 |
| `visual` | 该页使用的图/表；结果页必须有 |
| `seconds` | 该页计划秒数 |
| `notes` | 讲者备注：为什么这页在这里 + 怎么讲 + 过渡 |
| `transition` | 一句带到下一页的话 |
| `page_rhythm` | `dense` 或 `breathing`；连续 dense ≤ 3 页 |

### 结论式标题配方

```
[条件/对象] + [结果/判断] + [边界或对比]
例：高温下 A 的选择性优势来自氧空位，而非比表面积
例：5 分钟快报：三个对照实验排除了传质限制
```

反例与改法：

| 反例 | 问题 | 改法 |
|---|---|---|
| 研究背景 | 章节名 | 现有方法在 350 °C 以上失去选择性 |
| 结果（2） | 编号不是信息 | 掺杂样品在 400 °C 仍保持 92% 选择性 |
| 方法 | 听众不知道结论 | 用同位素交换区分表面氧与晶格氧 |
| 总结 | 空泛 | 选择性由氧空位控制，推广前需验证水汽条件 |

标题自检：遮住正文，只看标题，能否知道这页证明了什么？不能就重写。

### 一页一主张

- 一页出现两个并列结论就拆页；页数不够时砍第二个结论，不要把它塞进备注。
- 正文只放支撑该主张的图、数、短句；解释放讲稿。
- 页面文字上限：≤ 6 条要点、≤ 260 中文字；超出先拆页，不缩字号。
- 结果页的图必须与标题结论对应；图里有多个 panel 时只放大相关 panel，
  其余标注"完整数据见 backup"。

### 证据强度标注

| 强度 | 判据 | 使用方式 |
|---|---|---|
| `strong` | 直接测量、对照实验、可复现统计 | 可作为主结论 |
| `moderate` | 多条间接证据、机制一致但未直接测量 | 结论加"可能/支持" |
| `weak` | 单例、轶事、预印本、外推 | 只作 motivation 或明确标为假设 |

结论强度不得超过证据强度。`strong` 结论必须能指到具体图/表/页；
没有 locator 的数字不进页面。

### 证据映射（可复核的最小单位）

每条 evidence 至少包含：

```json
{"source": "materials/paper.pdf", "locator": "Fig.2a; §4.1",
 "strength": "strong", "note": "350 °C、1 bar 下的选择性"}
```

- `source` 用真实路径，不用"论文里"这种无法定位的描述；
- `locator` 精确到图号、表号、章节、页码或数据文件名/行号；
- 数值原样保留，不改写单位与有效数字；
- 找不到出处的论断：删除，或降级为 `hypothesis` 并写入 `uncertainty`。

## 5. 讲者备注与过渡

每页 notes 建议三段式（30–60 秒口语量）：

```
为什么这页在这里：上一页留下了"选择性随温度下降"的缺口。
怎么说：指出 350 °C 这个拐点，只讲一条对照，不念坐标轴。
过渡：如果氧空位解释成立，改变前驱体就应该复现这个拐点。
```

规则：

- 不照读页面文字；notes 与 title 逐字相同视为失败。
- 中文约 220 字/分钟，英文约 130 词/分钟；按此估算讲稿时长并与 `seconds` 对照。
- 标出停顿与重音位置（可用 `//` 表示停顿）。
- 每页结尾写一句过渡；最后一页除外（改为行动/结论句）。
- 时间检查点：25% 应讲完问题，50% 进入结果，75% 开始局限/讨论，90% 在结论页。

## 6. Q&A 准备

15 分钟报告准备 8–12 个问题；5 分钟快报至少 5 个。按类覆盖：

| 类别 | 典型问题 | 回答要点 |
|---|---|---|
| `method` | 为什么用 A 不用 B？对照是否充分？ | 设计理由 + 一个替代解释如何被排除 |
| `data` | 样本量/误差/显著性？ | 具体数值 + 图号 |
| `scope` | 换条件/换体系还成立吗？ | 边界 + 已做/未做的验证 |
| `literature` | 与某工作相比新在哪？ | 同一口径下的差异，不贬低他人 |
| `application` | 能落地吗？成本？ | 一个具体场景 + 限制 |
| `hostile` | 这与 X 的结论矛盾 | 先承认差异，再解释条件不同 |

每个回答：30 秒以内 + 证据位置（slide/图号/backup 页）。
不知道时的标准回答：

```
这个问题我没有直接数据。根据目前观察，我倾向于 X，但需要 Y 实验才能确认；
会后我把 Z 数据整理给您。
```

不编数据，不承诺未验证的结论。Q&A 中提到的补充材料必须真的存在于 backup 页。

## 7. 取舍记录与 backup

evaluator 会检查"从材料到成稿的取舍能否被复核"，因此计划里必须留下：

```json
{"cut": "文献综述细节", "reason": "15 分钟组会，听众已熟悉",
 "disposition": "backup", "target": 11}
```

- `disposition`：`dropped` / `backup` / `merged` / `deferred`；
- `must_cover` 的每一项都必须被至少一页 `covers` 覆盖；
- `nice_to_have` 被删时，写一条 tradeoff 说明原因；
- backup 页只答问、不讲，标题同样用结论句，notes 写"何时跳到这页"。

## 8. 快报、组会、答辩的差异

| 类型 | 核心问题 | 页数 | 必留 | 可删 |
|---|---|---|---|---|
| 5 min 快报 | 一个结果是否可信 | 5–7 | 问题、方法一句、主结果、含义 | 背景、局限单页、文献 |
| 15 min 组会 | 进度与风险 | 10–14 | 问题、方法、结果、风险/下一步 | 文献细节、实现细节 |
| 答辩 | 创新点与边界 | 20–50 | 问题、方法、结果、局限、贡献 | 教学式背景、冗余结果 |
| 跨学科 | 为什么与我有关 | 8–12 | 现象、机制示意、一个证据、含义 | 术语细节、消融 |

所有类型都遵守同一条底线：**标题连读成论证，证据逐页可定位，时间加总不超时。**

## 9. 失败模式

| 失败模式 | 识别信号 | 修复 |
|---|---|---|
| 论文搬家 | 页面出现整段摘要 | 压成一句结论 + 一张图 |
| 标题是标签 | 出现"结果/方法/背景" | 改成带条件与判断的句子 |
| 一页多点 | 标题下有 3 个并列结论 | 拆页，或把次要点移入 backup |
| 页数超时 | 逐页秒数之和 > 可用时间 | 删背景/方法细节，保结果与结论 |
| 时间假账 | section 分钟与逐页秒数对不上 | 以逐页秒数为准重排 section |
| 证据错配 | 图与标题结论无关 | 换图，或把结论降级 |
| 备注念稿 | notes 等于页面文字 | 改写为"为什么 + 怎么讲 + 过渡" |
| 无过渡 | 幕间跳转生硬 | 每页补一句 transition |
| Q&A 空白 | 没有预判问题 | 补 8 个问题与证据位置 |
| 过度声明 | 相关性写成因果 | 降级措辞并标注证据强度 |
| 编造补充 | backup 页没有的材料 | 删除或标为未完成 |

## 10. 交付前自检

- [ ] `throughline` 是听众结果句，不是主题词
- [ ] 3–5 幕，相邻幕有因果桥
- [ ] 逐页秒数之和 = 讲述时间（偏差 ≤ 15%）
- [ ] 每页标题是结论句，连读可复述论证
- [ ] 每个内容页有 claim + evidence（source + locator）
- [ ] 结果页有对应图/表，数值与源材料一致
- [ ] 每页 notes 非空、非页面文字复述，含过渡
- [ ] `must_cover` 全部被 `covers` 覆盖
- [ ] 有局限页（短报告可在结论页合并）
- [ ] Q&A ≥ 5（15 分钟 ≥ 8），每条有证据位置
- [ ] 取舍记录写清 dropped/backup 及原因
- [ ] `check_talk_plan.py` 返回 `ok: true`

## 11. 机器校验

```bash
python3 {SKILL_DIR}/scripts/check_talk_plan.py \
  --plan /app/work/talk-plan.json --json
python3 {SKILL_DIR}/scripts/check_talk_plan.py \
  --plan /app/work/talk-plan.json \
  --result /app/output/result.json \
  --root /app/output --json
```

退出码：`0` 通过，`1` 有错误，`2` 文件不可读/JSON 损坏。
报告含 `errors[]`、`warnings[]`、`stats`；`--strict` 把 warning 视为不通过，
用于交付前最后一遍。校验器只检查结构与一致性，不替代对科学内容的判断。
