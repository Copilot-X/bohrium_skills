# 长文档写作参考（章节索引、体例与一致性）

配合 `templates/chapter-index.json`、`templates/global-rules.json`、`templates/chapter-card.md`
和 `scripts/longform_audit.py` 使用。**task.md、organizer-edit-workorder.json 与
case.json 的优先级高于本文件**；材料未提供的章节不要补写。

## 1. 先定位生命周期阶段

| 阶段 | 当前任务 | 交付物 | 不做什么 |
|---|---|---|---|
| 选题 | 收窄问题、判断可行性 | 研究问题 + 范围 | 不写正文 |
| 开题 | 论证问题、方法、路线 | 开题报告 | 不假装有结果 |
| 文献综述 | 建立脉络、指出 gap | 综述章节 | 不罗列书目 |
| 研究设计 | 方法、样本、数据 | 方法章节 | 不编数据 |
| 逐章写作 | 按索引起草/修订 | 章节文件 + 检查点 | 不一次性生成全文 |
| 修改润色 | 按工单逐条改 | diff + 修订说明 | 不整章重写 |
| 统稿 | 术语/编号/引用一致 | consistency-report | 不新增未要求内容 |
| 答辩/发表 | 提炼贡献、预答问题 | PPT/回复 | 不夸大结果 |

学位层级决定 rigor 与篇幅：本科强调规范与方法正确；硕士要求创新点与讨论深度；
博士要求理论/方法贡献与独立研究能力。机构格式以官方规范为准。

## 2. 章节索引是地图

每章至少记：

```json
{"chapter_id":"ch03","order":3,"title":"第三章 结果","path":"chapters/ch03.md",
 "purpose":"回答 RQ2","words_target":6000,"status":"pending",
 "depends_on":["ch02"],"figures":["Fig.3-1"],"tables":["Table 3-1"]}
```

规则：

- `chapter_id` 与 `order` 唯一；`path` 必须真实存在。
- `purpose` 写“本章证明什么”，不是“本章写结果”。
- 缺章写进 `missing[]`，不要用标题补写。
- 修改模式只改工单指定项；未指定章节不动。

## 3. 全局规则先定死

在 `global-rules.json` 中一次确定：

- 术语表：每个概念一个规范译名，列出禁止变体。
- 缩写表：首次出现给全称，之后统一缩写。
- 编号：章-节、图-表、公式、附录的编号规则。
- 引用：GB/T 7714 / APA / IEEE / Vancouver 等，文内标注与文末列表一致。
- 字数预算：总预算分配到章，再分配到节。
- 时态/人称：结果用过去时、普遍结论用现在时；第三人称。

## 4. 每章写作卡

动笔前填 `templates/chapter-card.md`：

1. 本章核心论点（1 句）。
2. 对应研究问题与前后章承接。
3. 3–5 个论证单元：主张 → 证据 → 分析 → 边界。
4. 图表首次引用位置与解读句。
5. 术语/缩写与引用编号范围。
6. 目标字数与检查点。

写完做“反向大纲”：把各节首句连起来，看是否形成一条论证线；
偏离 `purpose` 就调整，而不是硬加过渡句。

## 5. 章节结构

| 章节 | 占比（参考） | 必须回答 |
|---|---|---|
| 绪论 | 8–12% | 问题是什么、为什么重要、gap 在哪、本文做什么 |
| 理论/文献 | 20–25% | 概念怎么界定、理论怎么解释、已有研究到哪 |
| 研究设计 | 10–15% | 方法是否匹配问题、样本/数据是否可得、如何分析 |
| 结果/案例 | 30–40% | 发现了什么、证据在哪、是否稳健 |
| 讨论 | 10–15% | 结果意味着什么、与已有研究的关系、边界 |
| 结论 | 8–10% | 回答 RQ、贡献、局限、展望 |

每章标准结构：开门见山（1–2 段）→ 背景/框架 → 核心论证（2–4 节）→
小结与过渡。每段一个主张，段首主题句；引文后必须有解释，不堆砌。

## 6. 跨章一致性

逐项核对：

1. **术语**：同一概念只用规范词；变体进 `terms` 表并由审计器报告。
2. **图表编号**：全局唯一；正文先引用后出现；每张图至少一句解读。
   图题/表题必须单独成行（审计器按行首识别题注），正文引用可出现在任意位置。
3. **交叉引用**：“见 3.2 节”必须指向真实存在的标题；章节移动后全文替换。
4. **引用编号**：全文连续；正文与文末双向核对；无孤儿条目。
   审计器只核对数字引用 `[n]`；APA/作者-年份等格式需人工核对。
5. **摘要/结论数字**：只从各章结果取数，与正文一致。
6. **章节承接**：每章末尾写“本章结论 → 下一章问题”的过渡。

## 7. 检查点与中断恢复

每完成一章立即：

```bash
python3 {SKILL_DIR}/scripts/longform_audit.py \
  --work /app/work --index /app/work/chapter-index.json \
  --rules /app/work/global-rules.json \
  --out /app/output/consistency-report.json --json
```

然后写 `checkpoint-<n>.json`：

```json
{"checkpoint": 3, "completed": ["ch01","ch02","ch03"],
 "next": "ch04", "open_issues": ["CI-004"], "words": 18200,
 "updated_at": "..."}
```

中断后从 `next` 继续，不重写已完成章节。审计器只报告问题，不替用户编内容。

全部章节完成后，用 `scripts/build_thesis.py` 合并并生成结果骨架：

```bash
python3 {SKILL_DIR}/scripts/build_thesis.py --work /app/work \
  --index /app/work/chapter-index.json \
  --out /app/output/thesis.md --result /app/output/result.json \
  --audit-report /app/output/consistency-report.json --json
```

脚本按 `order` 合并章节、生成目录与图表清单、统计字数，并把审计问题写入
`result.json` 的 `consistency_issues`；缺失章节只进 `missing_parts`，不补写。
最后用 `scripts/validate_result.py` 校验交付物路径与字段。

## 8. 字数与节奏

- 总字数按 task.md；无明确要求时按学位层级给保守预算，并说明假设。
- 超预算先压缩背景/综述，不删结果与证据。
- 单章超长拆成 3.1/3.2，并同步目录、交叉引用与索引。
- 单章过短先补证据/分析，不要用重复和套话凑字数。

## 9. 常见失败模式

| 信号 | 问题 | 修复 |
|---|---|---|
| 索引多章 status 为空 | 只写了开头 | 按优先级推进，先保骨架 |
| 同一概念多种译名 | 术语漂移 | 用 `global-rules.terms` 统一替换 |
| 各章引用从 [1] 开始 | 编号断裂 | 全文统一重编号 |
| 图表只出现不引用 | 正文与图表脱节 | 补首次引用与解读句 |
| 交叉引用指向空节 | 章节移动后未更新 | 审计器报告后全文替换 |
| 只在最后落盘 | 超时丢稿 | 每章检查点立即写文件 |
| 结论重复摘要 | 没有升华 | 回答 RQ、贡献、局限、展望 |
| 补写未提供章节 | 虚构内容 | 写 `missing_parts`，不生成 |
