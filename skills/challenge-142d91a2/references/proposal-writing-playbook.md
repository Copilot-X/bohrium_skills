# 开题报告 / 研究计划书写作参考

配合 `templates/proposal-plan.json`、`templates/proposal-brief.md`、
`scripts/check_proposal.py` 使用。**task.md、case.json 与材料优先**；没有预实验就写
“尚无预实验”，不要补数据。

## 1. 用 PICO 收窄问题

- **P**opulation/对象：研究谁/什么材料/什么系统。
- **I**ntervention/暴露：施加什么条件/变量。
- **C**omparison/对照：与什么比（基线、安慰剂、另一条件）。
- **O**utcome/结局：测什么指标，怎么判定。

缺一维就写清缺口；题目过大时缩小 scope 并说明取舍。

## 2. 假设必须可证伪

每条假设写：

```json
{"id":"H1","statement":"X 通过 Y 影响 Z","falsifiable_by":"若 Y 中介效应不显著且 X→Z 仍显著，则 H1 不成立"}
```

没有“什么结果会否定它”的假设不合格。

## 3. 目标—内容—方法—分析对齐

一行一个目标：

| 目标 | 假设 | 变量/对照 | 样本/功效 | 测量 | 分析 | 判据 |
|---|---|---|---|---|---|---|
| O1 | H1 | … | … | … | … | … |

- 每个目标有 `indicator`（可测指标）与 `criterion`（事先定义的判据）。
- 样本量给依据（功效分析/文献惯例），不能只写 n=30。
- 统计方法先于数据确定；多重比较写校正。

## 4. 技术路线

- 研究内容 → 关键科学问题 → 方法 → 技术路线 → 创新点形成闭环。
- 路线图节点用“输入→处理→输出”，每步有交付物；不要只画方框没有数据流。
- 方法必须匹配目标；列多种方法时说明各自解决哪个目标。

## 5. 时间线与风险

- 按季度/月排，里程碑可交付（数据/模型/论文/报告），标关键路径。
- 每阶段留缓冲；依赖关系写清。
- 每项高风险给触发信号、影响、Plan B；不写“无风险”。

## 6. 可行性、伦理与数据

- 可行性：理论、方法、数据、平台/条件、团队各写依据；缺什么写缺口。
- 伦理：涉及人/动物/隐私时写审批、知情同意、数据管理；不适用则说明。
- 材料未提供审批时写 `to_be_obtained` + 需补清单。

## 7. 事实台账与红队六问

`fact_ledger[]` 每条标：

- `confirmed`（材料明确）
- `user_stated`（用户口述）
- `to_supplement`（待补）
- `unusable`（不可使用）

红队六问：

1. 为什么重要？
2. 新在哪里？
3. 是否可做？
4. 有无前期基础？
5. 失败怎么办？
6. 是否符合指南/学位要求？

`one_minute_retelling` 用 5 句话复述问题、缺口、路线、价值、可验证结局。

## 8. 常见失败模式

| 信号 | 问题 | 修复 |
|---|---|---|
| 题目过大 | “研究 AI 与教育” | PICO 收窄 |
| 假设不可证伪 | 无判据/无否定结果 | 补 falsifiable_by |
| 方法堆砌 | 方法与目标不对应 | 按目标裁剪 |
| 时间线理想化 | 无缓冲/无依赖 | 加缓冲与关键路径 |
| 风险写“无” | 无 Plan B | 补风险与备选 |
| 伦理缺失 | 涉及人/动物无审批 | 补伦理与数据管理 |
| 事实与口述混用 | 未标来源 | 建 fact_ledger |

## 9. 交付前检查

- [ ] 问题符合 PICO，scope 有纳入/排除。
- [ ] 每条假设有 falsifiable_by。
- [ ] 每个目标有 indicator 与 criterion。
- [ ] 设计有材料/分组/测量/统计/样本依据。
- [ ] 时间线覆盖全部模块，里程碑可交付。
- [ ] 风险有 trigger/impact/plan_b，伦理有交代。
- [ ] `check_proposal.py` 返回 `ok: true`。
