# 成果转化写作规则（体裁优先 + 来源保真）

本文件是 `scripts/main.py` 的任务规则说明。**task.md 与 case.json 永远优先**；
脚本只负责归一化、取证、检查和落盘，不替代作者对体裁、受众和科学内容的判断。
主稿必须由模型按体裁写出完整文章；脚本不生成抽取式替代稿，也不会把缺失主稿
标记为 `completed`。

## 1. 体裁判定（先判体裁，再动笔）

| 体裁 | task.md 关键词 | 落盘文件名 | 必需结构 | 不得硬加 |
|---|---|---|---|---|
| `popular_article` | 科普、公众、大众、非专业、通俗 | `article.md` | 为什么重要 → 研究做了什么 → 看到了什么 → 意味着/不意味着什么 → 待回答的问题 | TRL、专利布局、融资、市场规模 |
| `project_application` | 项目申报、申报书、立项、可行性研究 | `proposal.md` | 问题 → 目标与考核指标 → 技术路线 → 现有基础 → 阶段计划 → 风险 → 预期成果 | 无来源的市场预测、无依据的预算 |
| `impact_statement` | impact statement、影响力陈述、社会影响 | `impact-statement.md` | 问题 → 贡献 → 受益对象 → 证据 → 边界 | 商业计划、投资回报 |
| `tech_brief` | 技术简报、技术报告、技术摘要 | `technical-brief.md` | 摘要 → 技术事实 → 成熟度 → 对比 → 风险/合规 → 下一步 | 无来源的竞品参数、虚构 TRL |
| `investment_memo` | 投资 memo、商业计划、融资、投资人 | `investment-memo.md` | 摘要 → 技术/成熟度 → IP → 场景/合作 → 证据/风险 → 里程碑 | 无来源的市场规模、财务预测 |
| `generic_rewrite` | 以上都不明确 | `rewrite.md` | 背景 → 材料给出的发现 → 意义/条件 → 边界 → 下一步 | 任何体裁专属章节 |

判定规则：

1. 先读 `case.json.task_instruction`，再读 `/input/task.md`；前者更具体时优先。
2. 关键词命中数接近（差距 < 2）时，`genre_confidence < 0.6`，必须在
   `uncertainty` 中写明，并少用体裁专属断言。
3. 任务描述里同时列举多种体裁（“可写成科普、申报或简报”）时，找
   “本次要求/输出/请写成”的限定句；找不到就按 `generic_rewrite` 处理。
4. 文件名以 task.md 明确要求为准；没有要求时用上表默认名。
5. 不要因为题目叫“成果转化”就默认写商业计划。

## 2. 受众适配

| 受众 | 背景 | 阅读目的 | 写法 |
|---|---|---|---|
| 公众 | 无专业背景 | 理解意义 | 先讲问题和影响；缩写首次展开；用类比但标注类比；少用参数表 |
| 评审专家 | 跨领域或同领域 | 评估可行性 | 目标—路线—验证一一对应；证据带条件；风险有触发信号 |
| 企业/合作方 | 跨领域 | 判断合作价值 | 交付物、集成方式、成熟度、合规与责任边界 |
| 投资人 | 跨领域 | 判断价值 | 壁垒、里程碑、资金用途、退出条件；市场数据必须有来源 |
| 政策/管理 | 跨领域 | 理解影响 | 受益对象、证据、适用条件、未验证部分 |

受众适配不是降低准确度：

- 关键数字、单位、条件、样本量、图表编号、引用不因读者变化而删除。
- 解释深度可以变，事实强度不能变。
- 同一概念全文只用一个说法；首次出现给定义或展开缩写。

## 3. 论断强度（fact / inference / speculation）

| 档位 | 判据 | 写法 | 禁止 |
|---|---|---|---|
| `fact` | 材料明写的数据、观察、条件 | 带数值、单位、条件、来源定位 | 剥离条件；把实验室结果写成量产 |
| `inference` | 由多条证据推出，原文未直说 | “由……可以推断”“这些结果提示” | 写成“已经证明” |
| `speculation` | 市场、成本、未来场景、外推 | “可能/若……则”“假设是……，待验证” | 写成事实；无假设、无验证路径 |

强度词表：

- 相关 ≠ 因果：材料只说“相关/伴随”时，不写“导致/因为”。
- 初步 ≠ 定论：`初步、提示、可能、在……条件下` 必须保留。
- 实验室 → 中试 → 现场 → 商业化是不同证据层级；没有上一级数据不得跳级。
- “首次/领先/填补空白”只在材料明确给出且可核实时使用，否则删除。

## 4. 数字、单位与条件保真

每个对外数字至少保留四件事：

1. **数值**：不改写、不四舍五入成新材料没有的数。
2. **单位**：`%`、`°C`、`bar`、`h`、`mg/L` 等与源文一致；中文单位可保留。
3. **条件**：温度、压力、pH、浓度、时间、样本量、实验/中试/现场规模。
4. **比较对象/分母**：跟谁比、占多少、n 是多少、百分比的分母是什么。

规则：

- 范围值不要擅自取中点；需要近似时写“约”并保留范围。
- 百分比、百分点、倍数不能互换。
- 同一指标在不同条件下的多个值可以并存，不能合并成一个“代表值”。
- 图表编号、表头、脚注、样本身份要与源文一致；正文与图表冲突时先回源核对，
  无法解决就并列披露，不替作者裁定。
- 单位换算必须显式写出换算关系；脚本只做常见别名归一（`℃`/`°C`、`小时`/`h`），
  不做物理换算。
- 材料没有的数字、竞品参数、市场规模、成本、效率提升幅度一律不写。

## 5. 引用与来源定位

- 每条关键事实在 `evidence_map` 中保留 `path` + `locator`（行号/页/段落）。
- 正文可以不带行号，但 `result.json` 必须能逐条回溯。
- 源文的 `[1]`、作者-年份、DOI、图/表编号在改写中保留；不能把引用挪到
  不支持的句子上。
- 新增外部知识（教材常识、行业数据）不算“保留来源”；没有来源就不写。
- 引用缺失时：保留原句并标记 `citation_missing`，不要补造参考文献。

## 6. 内容取舍（keep / compress / delete）

优先级从高到低：

1. **必须保留**：关键结论、关键数字与单位、条件、样本量、统计口径、图表编号、
   引用、限定语、术语定义。
2. **可以压缩**：背景综述、文献回顾、方法细节、重复描述、仪器型号。
3. **可以删除**：与目标体裁无关的章节、材料外的商业判断、保密内容、空泛口号。

压缩不是删证据：删掉方法细节时，保留理解结论所需的条件和对照。
每一条取舍写入 `content_decisions` 与 `change_log`，说明 keep/compress/delete
及理由。

## 7. 术语与表达一致

- 建立术语表：中文名、缩写、英文名、定义、首次出现位置。
- 缩写首次出现写“中文全称（English full name，ABBR）”，后文统一用 ABBR。
- 同一概念不混用多个译名；跨体裁替换时在术语表记录映射。
- 类比只用于解释，不能给材料没有的结构、机制或因果补细节。

## 8. 异常处理

| 情况 | 处理 | 结果字段 |
|---|---|---|
| 体裁不明确 | 选 `generic_rewrite`，少用体裁专属断言 | `uncertainty` + `genre_confidence` |
| 材料缺关键数据 | 正文写“材料未提供”，不补造 | `limitations` + `unresolved_questions` |
| 数据自相矛盾 | 保留各自条件，并列披露；不擅自选一个 | `uncertainty`（possible_data_conflict） |
| 引用缺失 | 保留原句，标 `citation_missing` | `uncertainty` |
| 市场数据无来源 | 只做定性判断；`market_data: not_available` | `limitations` |
| 专利状态不明 | `ip.status: not_provided`，提示核实 | `unresolved_questions` |
| 材料涉密/未公开 | 不写入对外稿；列入 `restricted` | `restricted` |
| PDF/图片无法解析 | 记录不可读；用运行时 PDF/OCR 工具；不猜内容 | `uncertainty` |
| 篇幅与内容冲突 | 先保关键证据，压缩背景；说明取舍 | `change_log` |
| 脚本/检查失败 | 主稿照常落盘；把失败写入 uncertainty | `checks` + `uncertainty` |

## 9. 逐段可复核（change log）

`change_log` 至少覆盖：

- 每个正文小节的动作（keep / compress / rewrite / add / delete）。
- `before` 用源文原句或紧邻转述，`after` 用成稿实际句子。
- 理由写“为什么这样改”，不是“改得更好了”。
- 未解决的确认项写入 `unresolved_questions`，不要藏在正文里。

## 10. 交付前验收

- [ ] 主稿是完整文章/材料，不是提纲、建议或片段润色。
- [ ] 体裁、受众、篇幅与 task.md 一致；没有硬加体裁不需要的章节。
- [ ] 每个关键数字有单位、条件、比较对象；与源文一致。
- [ ] 没有材料外事实；推断/推测有标记与假设。
- [ ] 关键论断在 `evidence_map` 中有路径与定位。
- [ ] `deliverable.path` 指向真实文件；DOCX 可打开。
- [ ] `preserved_facts`、`evidence_map`、`change_log` 非空。
- [ ] 保密内容未进入正文；已列入 `restricted`。
- [ ] 所有检查失败与材料缺口都已写入 `uncertainty` / `limitations`。
